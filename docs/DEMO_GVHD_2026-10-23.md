## 2. Khởi động từ terminal VS Code

Khuyến nghị dùng Docker cho cả ứng dụng nhưng điều khiển bằng terminal VS Code. Bản này dùng đúng volume model đã có và có ffprobe để đo MP4.

1. Mở Docker Desktop, chờ Engine running.
2. Mở folder `C:\Project\vedu-lms-capstone` trong VS Code.
3. Dừng terminal backend/Vite native bằng Ctrl+C nếu đang chạy; không chạy hai backend cùng cổng.
4. Mở Terminal → New Terminal, chọn PowerShell:

```powershell
Set-Location C:\Project\vedu-lms-capstone
docker version
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
docker compose -f docker-compose.yml -f docker-compose.dev.yml ps -a
Invoke-RestMethod http://localhost:3000/api/health
Invoke-RestMethod http://localhost:8080/api/health
```

5. `db`, `ml`, `backend` cần healthy; frontend cần Up. `demo-seed` **Exited (0)** là hoàn thành tác vụ một lần, không phải lỗi.
6. Mở `http://localhost:8080`. Không mở 5173 khi chưa chạy Vite.

Hai file Compose giữ cổng database ở `127.0.0.1:5432`, thuận tiện mở pgAdmin lúc GVHD hỏi. Backend gọi database bằng hostname `db`; ứng dụng quản trị chạy trên Windows dùng `127.0.0.1`.

Nếu khởi động lần đầu, build và tải image có thể mất thời gian. Làm tối nay, không chờ đến lúc báo cáo. Hai CSV Kaggle cần dùng đã có trong `ml-core/data`; không cần nhập lại hoặc huấn luyện lại chỉ để bật app.

### C. 03:00–07:00 — ML, HUSPM và lộ trình

Phần này cùng lúc minh chứng ba dòng: khuyến nghị lộ trình; cài mô hình; tích hợp kết quả mô hình.

1. Admin `/admin/mining`, chọn experiment Kaggle Recommender SUCCEEDED → **Xem kết quả**. Mở **Nguồn, SHA256 và tham số**: nguồn CSV, chia thời gian 70/15/15, seed 42, số user/item, artifact hash. File model đang tồn tại trong ML volume.
2. Chỉ bảng BPR-MF, GRU-next-item, Item-KNN, HUSPM-only, Popularity, ablation và hybrid. Hai mô hình huấn luyện chính là BPR và GRU; KNN từ scikit-learn là baseline fitted trên cùng train, không phải mô hình pretrained.
3. Mở một mẫu HUSPM, đọc chuỗi, support và utility. Ví dụ giải thích miệng: chuỗi `A[1] → B[2] → A[8] → B[4]`, mẫu `A→B` có utility lớn nhất 12 trong chuỗi này; không cộng mọi embedding thành 20. SWU giúp cắt nhánh. Cài đặt tên VEDU-PrefixProjection-HUSPM, giới hạn singleton-itemset và max_length; không nhận là HUSP-SP nguyên bản.
4. Bấm **Chạy thử lịch sử Kaggle**; chỉ một mẫu lịch sử trước target và top-3. Nói đây là replay ngoài hệ thống; 5 mẫu chọn đầu tiên không đại diện toàn dataset và không phải người học VEDU.
5. Student `/student/learning-path`, chọn khóa Office 365 tham chiếu đã ghi danh/chuẩn bị lịch sử. Nhập: Phục vụ công việc; Mới bắt đầu; Hành chính – hồ sơ văn phòng; Đọc, xem và thực hành; 3600 giây/tuần; 4 tuần; 4 phương án. Bấm **Tạo và so sánh lộ trình**.
6. Chỉ nguồn **MODEL_CONSTRAINED**, experiment và căn cứ khi có dữ liệu hợp lệ; so hai phương án về tập bài, thời gian, tiên quyết, lý do. Chọn phương án → refresh → chọn lại khóa → thấy lựa chọn đã lưu. Gửi đánh giá 1–5 nếu đủ thời gian.
7. Nếu còn 15–20 giây, chọn Word thực hành để chỉ nguồn CURRICULUM khi chưa có mô hình trong miền. Không đổi mapping để ép hiện nhãn MODEL.

Nói: “Mô hình xếp hạng bài ứng viên; bộ lập kế hoạch giữ điều kiện tiên quyết và ngân sách, loại bài đã hoàn thành, rồi sinh những phương án thực sự khác nhau. Giải thích hiện được tạo từ căn cứ và điểm mô hình, chưa gọi dịch vụ LLM bên ngoài.”

Không bắt buộc huấn luyện mới ngay trong live. Nếu muốn chứng minh nút train: đồng bộ job cũ trước, bấm train sớm trong buổi, dùng experiment thành công đã có để giải thích trong lúc chờ. Không hứa thời gian hoàn tất và không đổi môi trường native/Docker giữa buổi.

Nếu nguồn ra CURRICULUM: kiểm tra member, ghi danh, mapping cùng nội dung, có lịch sử, ML healthy và có artifact. Nếu đã học gần hết khóa hoặc ràng buộc tạo các danh sách giống nhau, số phương án có thể ít hơn 4; đó không tự động là lỗi.

Kết quả seed 42 để trả lời trung thực:

| Dataset | Mô hình | Recall@3 ở test hợp lệ | Recall@3 trên toàn target |
|---|---|---:|---:|
| Logs 5 module | BPR | 0,6074 | 0,6074 |
| Logs 5 module | Hybrid | 0,5973 | 0,5973 |
| Recommender | BPR | 0,1429 | 0,0157 |
| Recommender | Hybrid | 0,0952 | 0,0104 |

Recommender chỉ có 42/383 target đủ lịch sử/catalog; 341 target cold được tính miss ở test_all_targets. Hybrid chưa vượt BPR; trên Logs, Popularity Recall@3 = 0,6107 cũng nhỉnh hơn BPR. Không chọn một con số đẹp rồi nhận mô hình vượt trội. Chương 5 cần so nhiều seed và báo cáo phạm vi rõ.

## Phụ lục tạo teacher phụ trước buổi demo

Chạy khi app 8080 đã hoạt động, trong terminal riêng không chiếu lên slide. Chọn một username mới, ví dụ `gv_demo2`. Nếu đã tồn tại, đăng nhập bằng tài khoản có sẵn hoặc đổi username/email đồng bộ; không tạo nhiều tài khoản trùng.

```powershell
$veduBase = 'http://localhost:8080/api'
$veduAdminCredential = Get-Credential -UserName admin -Message 'Nhap tai khoan ADMIN hien tai'
$veduTeacherCredential = Get-Credential -UserName gv_demo2 -Message 'Dat mat khau teacher phu, du hoa thuong so va ky tu dac biet'
$veduAuth = $null
try {
    $veduLoginBody = @{
        username = $veduAdminCredential.UserName
        password = $veduAdminCredential.GetNetworkCredential().Password
        expectedRole = 'ADMIN'
    } | ConvertTo-Json
    $veduAuth = Invoke-RestMethod "$veduBase/auth/login" -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($veduLoginBody))
    $veduTeacherBody = @{
        username = $veduTeacherCredential.UserName
        password = $veduTeacherCredential.GetNetworkCredential().Password
        fullName = 'Giang vien demo 2'
        email = "$($veduTeacherCredential.UserName)@vedu.local"
        phone = '0901234567'
        role = 'TEACHER'
    } | ConvertTo-Json
    Invoke-RestMethod "$veduBase/users" -Method Post -Headers @{Authorization="Bearer $($veduAuth.accessToken)"} -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($veduTeacherBody)) | Select-Object userId,username,role
}
finally {
    if ($veduAuth) {
        $veduRevokeBody = @{refreshToken=$veduAuth.refreshToken} | ConvertTo-Json
        Invoke-RestMethod "$veduBase/auth/revoke" -Method Post -ContentType 'application/json' -Body $veduRevokeBody | Out-Null
    }
    $veduLoginBody = $null
    $veduTeacherBody = $null
    $veduRevokeBody = $null
    $veduAuth = $null
    $veduAdminCredential = $null
    $veduTeacherCredential = $null
}
```

Script dùng API quản trị đang có, tạo một tài khoản thật và chỉ thu hồi phiên admin vừa mở trong terminal. Không chạy script này nếu chưa định tạo teacher phụ; cần đổi mật khẩu/khóa tài khoản demo sau khi kết thúc đợt dùng thử nếu không dùng tiếp.
